# Sub-agents on another provider

Status: Shipped
Date: 2026-10-30

## Problem

Claude Code and Codex each spawn sub-agents of their own kind. To get a second opinion from the other one, such as a Codex review from a Claude thread, agents ran `codex exec` or `claude -p` in a shell and polled for an output file with `sleep`. HinaCode could not see that session: no row in the Agents tab, no tool calls, no stop button, no approvals, and it kept running after the user stopped the turn.

## User flow

1. The agent calls the hinacode `run_agent` tool with a provider, a short description and a prompt.
2. The thread's Agents tab gets a row with that provider's icon and the description. The tool call in the transcript opens the sub-agent's view, with its prompt and tool calls.
3. Approvals and questions from the sub-agent appear in the thread like the thread's own.
4. When it finishes, its last reply is the tool result. Stopping the row, or the thread's turn, interrupts it and the tool returns an error.

## Design

- `mcp/tools/agents.ts` defines `run_agent` and calls `AgentRunner.runAgent`.
- `runAgent` needs the caller's running turn. It calls `provider.runTurn` with a session id of `<threadId>:agent:<uuid>`, in the thread's workspace, with its access mode, MCP credential and instructions. It defaults to the thread's model on the same provider, or the provider's first listed model, and to the default account of another provider.
- The sub-agent's tool calls, file changes, approvals and questions go through the parent turn's `handle`, so they persist in the thread's transcript. Tool calls carry `parentCallId`, set to the spawning `run_agent` call (`agents/runAgent.ts` finds it by name and prompt) or to the session id when it is not found.
- Its text after the last tool call is the reply. `Subagent.provider` tells the renderer which icon to draw.
- `subagents.stop` and the end of the parent turn call the provider's `interrupt` on the session id. `closeSession` runs when the sub-agent ends.

## Out of scope

- Steering a running sub-agent, or resuming one: each call is a fresh session.
- Background runs. The tool blocks until the sub-agent ends.
- Running it on another machine. `create_thread` with `machine` covers that.

## Verification

- `mcp/server.integration.test.ts` runs a scripted Codex sub-agent from a Claude thread and checks the reply, the Agents tab row, the transcript's `parentCallId`, and stopping it.
- `agents/runAgent.test.ts` finds the spawning call in Claude and Codex transcripts.
