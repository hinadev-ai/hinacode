# Chats

Status: Building
Date: 2026-10-24

## Problem

Asking an agent a question that has nothing to do with a repository meant picking a project first, so the agent started in some unrelated checkout, read its `CLAUDE.md`, and loaded its skills. People added a dummy folder as a project to get around it.

## User flow

1. Click the chat bubble next to the sidebar filter, or `+` on the Chats group, or pick Chats in the `mod+n` picker. A thread opens in Chats with the composer focused.
2. The composer has no branch or worktree picker, since there is no repository to branch. When a cloud is connected, the machine picker moves the chat to it.
3. Chats is a group in the Threads tab like a project, with a chat icon and no project menu. Every machine's chats share the group, as one repository's machines do. Pinning, search and the inbox treat chats like any thread.
4. Each chat works in an empty folder of its own, so one chat never sees another's files. Archiving a chat deletes its folder; unarchiving starts it again empty.

## Design

- `project.kind` is `folder` or `chats` (migration `0021`). A partial unique index allows one `chats` row per database.
- `Projects.ensureChats(rootPath)` makes the folder and upserts the row. `makeAppLayer` runs it at startup with `<dataDir>/chats`, so the desktop and every `hinacode serve` cloud each have one. The upsert moves the row when the data directory moves.
- A chat works in `<chats rootPath>/<threadId>`. `makeActiveWorkspace` derives it, so no thread row stores a path. `Threads` makes the folder on create and unarchive, and deletes it on archive and delete. Migration `0024` archives the chats from before, which shared the project folder.
- `groupProjects` puts every machine's chats project in one `chats` group, so the composer's environment picker moves an unstarted chat between machines like any thread.
- No rpc changes: `threads.create` takes the chats project's id like any other.
- The renderer names the chats project in the UI's language in `projectsAtom`, so every surface that shows a project name says Chats. `useIsChat` hides the workspace picker and swaps the empty thread hint.

## Out of scope

- Starting a chat on a cloud from the header button. It always starts on this desktop, and the composer's machine picker moves it.
- Keeping a chat's files after it is archived. Archive is the end of a chat; anything worth keeping belongs in a project.

## Verification

- `Projects.integration.test.ts`: `ensureChats` keeps one chats project and moves it to the latest folder.
- `Threads.integration.test.ts`: two chats get different folders, archiving deletes one, and unarchiving makes it again empty.
- `projectGroups.test.ts`: chats on this machine and a cloud are one group.
- `verify-hinacode`: on a fresh profile the sidebar shows Chats. New chat opens a thread with no workspace picker. A Sonnet turn answers from `<dataDir>/chats`.
