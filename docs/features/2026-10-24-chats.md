# Chats

Status: Building
Date: 2026-10-24

## Problem

Asking an agent a question that has nothing to do with a repository meant picking a project first, so the agent started in some unrelated checkout, read its `CLAUDE.md`, and loaded its skills. People added a dummy folder as a project to get around it.

## User flow

1. Click the chat bubble next to the sidebar filter, or `+` on the Chats group, or pick Chats in the `mod+n` picker. A thread opens in Chats with the composer focused.
2. The composer has no workspace picker, since there is no repository to branch. The Conversation toggle starts on, so the agent loads no user skills or commands.
3. Turn Conversation off to load your user skills in this chat. It applies from the next turn, as in any thread.
4. Chats is a group in the Threads tab like a project, with a chat icon and no project menu. Pinning, archiving, search and the inbox treat chats like any thread.

## Design

- `project.kind` is `folder` or `chats` (migration `0021`). A partial unique index allows one `chats` row per database.
- `Projects.ensureChats(rootPath)` makes the folder and upserts the row. `makeAppLayer` runs it at startup with `<userData>/chats`, so the desktop and every `hinacode serve` cloud each have one. The upsert moves the row when the data directory moves.
- `Threads.create` sets `userSkills` to `project.kind === "folder"`, so a chat starts in conversation mode. No rpc changes: `threads.create` takes the chats project's id like any other.
- The renderer names the chats project in the UI's language in `projectsAtom`, so every surface that shows a project name says Chats. `useIsChat` hides the workspace picker and swaps the empty thread hint.

## Out of scope

- A folder per chat. Every chat shares `<userData>/chats`, so files one chat writes are visible to the next.
- Starting a chat on a cloud from the header button. It always uses this desktop's chats project. A cloud's Chats group still has its own `+`.
- Muse Code has no way to hide skills, so its chats load them.

## Verification

- `Projects.integration.test.ts`: `ensureChats` keeps one chats project and moves it to the latest folder.
- `Threads.integration.test.ts`: a chat thread starts with `userSkills` off, a folder thread with it on.
- `verify-hinacode`: on a fresh profile the sidebar shows Chats. New chat opens a thread with no workspace picker and Conversation on. A Sonnet turn answers from `<userData>/chats`, and turning Conversation off sets `userSkills`.
