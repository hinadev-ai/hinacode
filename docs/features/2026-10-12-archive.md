# Archive threads, and find them in the sidebar

Status: Shipped
Date: 2026-10-12

## Problem

A developer who runs many agents ends up with a sidebar full of finished threads. Today the only way to put one away is "settle", which always deletes the worktree, leaves the thread in the list dimmed, and cannot be undone. With several projects open there is also no way to narrow the sidebar to the project or thread they are looking for, so finding the one that needs them costs a scroll.

## User flow

1. The sidebar has two tabs, Threads and Archived, and a filter field above them. Typing matches thread titles and project names. The project filter button next to the field picks which projects the sidebar shows.
2. `Archive` in a thread's row menu moves it to the Archived tab at once. When the Archive settings remove worktrees and the thread has one, a confirmation names the folder first, because that part cannot be undone.
3. The Archived tab lists archived threads under their project, newest first. Clicking one opens it read as before. `Unarchive` puts it back in Threads, idle, in the project root when its worktree is gone.
4. Settings, Archive:
   - "Archive when all linked pull requests merge", off by default. kkcode checks the threads with linked pull requests every few minutes and archives each one whose links are all merged.
   - "Remove the worktree when archiving", off by default. Deletes the worktree folder, and its branch when merged into its base.

## Design

- `ThreadStatus` drops `settled`. `archived` is the only resting state. Migration `0009_archive` rewrites `settled` rows to `archived`.
- `Settings.archive = { whenMerged: boolean, removeWorktree: boolean }`.
- `threads.settle` becomes `threads.archive`. It refuses a busy thread, removes the worktree when `removeWorktree` is on, closes the thread's terminals, and marks the thread archived. All of that runs inside `Worktrees.exclusive`, the same lock a turn holds while it marks its thread running, so an archive accepted after a slow `gh` lookup cannot hide a turn that started meanwhile. `threads.unarchive` sets it back to `idle`.
- `AutoArchive` is a scoped loop in main. Every 3 minutes, when `whenMerged` is on, it reads every linked pull request of threads that are not archived and not busy, asks `gh` for each status, archives the threads whose links are all `merged`, and pushes `thread.updated`.
- The sidebar search query, the active tab and the project filter live in the `ui` store. The project filter is persisted in `localStorage`; an empty filter, or one whose projects are all gone, shows every project. Reordering is off while a query is active, since dragging a partial list cannot express a full order.

## Out of scope

- Per-thread choice of removing the worktree in the dialog. The setting decides.
- Archiving from the MCP server or an automation.
- Searching message bodies from the sidebar. The command palette's `%` search does that.
