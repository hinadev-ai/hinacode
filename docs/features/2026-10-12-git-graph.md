# Git graph

Status: Building
Date: 2026-10-12

## Problem

An agent works on a branch in its own worktree and commits as it goes. To review what it did, the developer leaves kkcode for a terminal (`git log --graph`) or another editor, just to see which commits are on the branch, how the branch relates to `main`, and what one commit changed. The Changes section only shows the combined diff against the base ref, so commit boundaries, merges and tags are invisible.

## User flow

1. Open a thread and its side panel, then the History view.
2. The view lists the repository's commits newest first, across all branches: a lane graph on the left, then ref chips, the subject, the author and a relative time. `HEAD` and the thread's branch are the only violet chips.
3. Click a commit, or move to it with Up and Down. Its diff opens below the list in a split whose divider can be dragged, or moved with the arrow keys when focused.
4. Enter hides or shows the diff. Home and End jump to the newest and the oldest loaded commit.
5. Scrolling near the end loads more commits. The header refresh button reloads, and so does any `worktree.updated` push for this checkout or a status change of the thread, such as a turn ending.

## Design

- **Data.** `GitCommit { hash, parents, subject, author, authoredAt, refs }` and `CommitDiff { patch, files }` in `src/shared/domain.ts`.
- **rpc.** `git.log { root, limit? }` returns up to `limit` commits (default 200, at most 10000). `git.show { root, hash }` returns one commit's patch and changed files. Both are handled in `ipc.ts`.
- **Trust boundary.** `root` comes from the renderer, so the handler only accepts a project `rootPath` or a live worktree `path` that kkcode recorded. Anything else fails with `UnknownRootError` before git runs. `hash` must be 7 to 64 hex digits, so it can never be read as a git option.
- **Git.** `Git.log` runs one `git log --branches --remotes --tags HEAD --topo-order --date=iso-strict -z` with NUL-separated fields, parsed by the pure `parseLog`. It lists refs explicitly instead of `--all`, because `--all` also walks the stash, which every worktree shares, and tool-private refs such as editor checkpoints. Those show up as disconnected lanes that are not history. `Git.show` runs `git show --format= --patch --diff-merges=first-parent`, so a merge shows what it brought into its first parent instead of a combined diff the viewer cannot parse. Output format is pinned against user config the same way `Worktrees.changes` does it.
- **Layout.** `layoutGraph(commits)` in `src/renderer/lib/gitGraph.ts` is pure. It walks commits in topological order with an array of lanes, each holding the hash it waits for. A commit takes the leftmost lane waiting for it, or the first free one. Its first parent continues in its lane, other parents join a lane already waiting for them or take a free one. A row's `edges` are the line segments from its node's center line to the next row's center line, so each row's SVG draws the lower half of its own edges and the upper half of the previous row's, and no row needs to know about any other.
- **View.** `GitGraphView` virtualizes rows with `@legendapp/list` at a fixed 28 px row height. The SVG per row uses bezier curves for lane changes. Lane colors come from six `--graph-lane-*` tokens in `index.css`, set for light and dark. An edge takes the color of its higher lane, which is the branch side. The diff renders each file with `@pierre/diffs` `FileDiff`, themed like the Changes section.
- **Accessibility.** The list is a `listbox` with `aria-activedescendant`. Each row is an `option` named "<subject> by <author>". The selected row has an inset focus ring while the list has focus. The split divider is a focusable `separator` with `aria-valuenow`.
- **Mount.** The view lives in the thread side panel. It will move into the side panel activity bar as the `git` view once that lands.

## Out of scope

- Writing to git: checkout, cherry-pick, reset, branch create. The graph is for reviewing what an agent did, and agents own their worktree.
- Filtering by branch or author, and search. Add them when a long-lived repository makes the list hard to scan.
- Watching `.git` for new commits. A turn ending and the refresh button cover the agent loop without a file watcher.
- Rename detection in commit diffs. Renames show as a delete and an add, matching the Changes section.

- `lib/gitGraph.test.ts` lays out a linear history, a fork and a merge.
- `ipc.integration.test.ts` builds a real repository with a branch, a merge and a tag, reads it over rpc, shows a merge commit, and refuses an unknown root and an option-like hash.

- Performance: a 5000 commit repository, layout time and scroll smoothness below.
