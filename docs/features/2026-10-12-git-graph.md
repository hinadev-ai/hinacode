# Git graph

Status: Shipped
Date: 2026-10-12

## Problem

An agent works on a branch in its own worktree and commits as it goes. To review what it did, the developer leaves kkcode for a terminal (`git log --graph`) or another editor, just to see which commits are on the branch, how the branch relates to `main`, and what one commit changed. The Changes section only shows the combined diff against the base ref, so commit boundaries, merges and tags are invisible.

## User flow

1. Open a thread and pick Git in the side panel's activity bar, or press `mod+shift+g`.
2. The view lists the checkout's commits newest first, across all branches: a lane graph on the left, then a ref chip, the subject, the author when the panel is wide enough, and a relative time. The thread's branch and `HEAD` are the only violet chips.
3. Click a commit, or move to it with Up and Down. Its diff opens below the list in a split whose divider can be dragged, or moved with the arrow keys when focused. The panel widens while a diff is open, like it does for a file in Changes.
4. Enter hides or shows the diff. Home and End jump to the newest and the oldest loaded commit.
5. Scrolling near the end loads more commits. The header refresh button reloads, and so does any `worktree.updated` push for this checkout or a status change of the thread, such as a turn ending.

## Design

- **Data.** `GitCommit { hash, parents, subject, author, authoredAt, refs }` and `CommitDiff { patch, files }` in `src/shared/domain.ts`.
- **rpc.** `git.log { root, limit? }` returns up to `limit` commits (default 200, at most 10000). `git.show { root, hash }` returns one commit's patch and changed files. Both are handled in `ipc.ts`.
- **Trust boundary.** `root` comes from the renderer, so the handler only accepts a project `rootPath` or a live worktree `path` that kkcode recorded. Anything else fails with `UnknownRootError` before git runs. `hash` must be 7 to 64 hex digits, so it can never be read as a git option.
- **Git.** `Git.log` runs one `git log --branches --remotes --tags HEAD --topo-order --date=iso-strict -z` with NUL-separated fields, parsed by the pure `parseLog`. It lists refs explicitly instead of `--all`, because `--all` also walks the stash, which every worktree shares, and tool-private refs such as editor checkpoints. Those show up as disconnected lanes that are not history. `Git.show` runs `git show --format= --patch --diff-merges=first-parent`, so a merge shows what it brought into its first parent instead of a combined diff the viewer cannot parse. Output format is pinned against user config the same way `Worktrees.changes` does it.
- **Layout.** `layoutGraph(commits)` in `src/renderer/lib/gitGraph.ts` is pure. It walks commits in topological order with an array of lanes, each holding the hash it waits for. A commit takes the leftmost lane waiting for it, or the first free one. Its first parent continues in its lane unless a lane to its left already waits for it, so a main line keeps its lane when a branch to its right forked from the same commit. Other parents join a lane already waiting for them or take a free one. A row's `edges` are the line segments from its node's center line to the next row's center line, so each row's SVG draws the lower half of its own edges and the upper half of the previous row's, and no row needs to know about any other.
- **View.** `GitGraphView` virtualizes rows with `@legendapp/list` at a fixed 28 px row height. The SVG per row uses bezier curves for lane changes. Lanes are 12 px wide and narrow down to 8 px to keep the graph within 112 px, so the subject keeps room in a 24 rem panel; a history needing more lanes is clipped on the right. A row shows one ref chip, preferring the thread's branch, then `HEAD`, and counts the rest. `chipRefs` drops `<remote>/HEAD` and a remote branch that sits where its local branch does. Lane colors come from six `--graph-lane-*` tokens in `index.css`, set for light and dark. An edge takes the color of its higher lane, which is the branch side. The diff renders each file with `@pierre/diffs` `FileDiff`, themed like the Changes section.
- **Accessibility.** The list is a `listbox` with `aria-activedescendant`. Each row is an `option` named "<subject> by <author>". The selected row has an inset focus ring while the list has focus. The split divider is a focusable `separator` with `aria-valuenow`.
- **Mount.** `GitGraphView` is the `git` entry in the side panel view registry, `sidePanel/views.ts`. A thread without a worktree, or whose worktree was removed, shows the project root's history.

## Out of scope

- Writing to git: checkout, cherry-pick, reset, branch create. The graph is for reviewing what an agent did, and agents own their worktree.
- Filtering by branch or author, and search. Add them when a long-lived repository makes the list hard to scan.
- Watching `.git` for new commits. A turn ending and the refresh button cover the agent loop without a file watcher.
- Rename detection in commit diffs. Renames show as a delete and an add, matching the Changes section.

## Verification

- `services/Git.test.ts` parses recorded `git log` output: refs, merges, root commits, subjects with separators.
- `lib/gitGraph.test.ts` lays out a linear history, a fork and a merge.
- `ipc.integration.test.ts` builds a real repository with a branch, a merge and a tag, reads it over rpc, shows a merge commit, and refuses an unknown root and an option-like hash.
- In the app: open a thread on this repository and compare the graph with `git log --graph --oneline --all | head -40`. Screenshot light and dark.
- Performance, on a generated 5000 commit repository with 366 branches and 13 lanes: `git.log` for 5000 commits answers in about 100 ms over rpc, and `layoutGraph` takes 4 to 6 ms (median of 20 runs, Apple Silicon, Node 24). Scrolling the full list at 120 rows per frame for 4 s held a median frame of 8.3 ms and a worst of 10.3 ms on a 120 Hz display, with no frame over 33 ms.
