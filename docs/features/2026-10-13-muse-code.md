# Muse Code threads

Status: Building
Date: 2026-10-13

## Problem

Meta shipped Muse Code, its terminal coding agent, with Muse Wonder (`muse-wonder-1.0`) and Muse Wonder Full (`muse-wonder-full-1.0`). Muse Wonder Full only runs inside Muse Code on the Power Usage and Maximum Usage plans; the pay-as-you-go Model API does not serve it. A developer who wants to try it next to Claude Code and Codex has to leave hinacode for a terminal, and loses the worktree per thread, the approval cards, the PR links and the status bar.

## User flow

1. The composer's agent picker lists Muse Code with the Meta logo, next to Claude Code and Codex. The model picker lists what the signed-in plan offers, such as Muse Wonder Full 1.0, and the effort picker shows each model's tiers.
2. A turn streams text, reasoning, tool rows, approval cards and questions like the other agents, with Steer and Stop. `bash` shows as a command row, and `read_file`, `write_file`, `edit_file`, `search`, `web_fetch` and `web_search` get the matching icons.
3. The access picker maps to Muse's approval modes, and a change applies to the running turn at once. Muse's OS sandbox stays on, with the network allowed.
   - Supervised asks before commands and edits.
   - Auto runs freely in the sandbox, network included, and asks before writing outside the workspace.
   - Full access never asks.
4. "Allow" approves the whole command the card shows. Muse splits a compound shell command into stages and asks per stage; hinacode answers every stage with the user's one decision.
5. The status bar shows the thread's tokens per model, counting Muse's sub-agents and reminder agents, and a Muse Code group with the 5-hour and weekly windows once a Muse turn has run.
6. Settings > Models lists Muse Code with its CLI login and a default model. It has no "Add account" button, for the reason under Out of scope.

## Design

- `ProviderId` gains `"muse"`. Migration `0011_muse_provider` swaps the `provider` column of `thread` and `automation` the way `0006` did, so the CHECK accepts `muse` without cascading deletes.
- `Settings.defaultModel` and `defaultAccount` gain `muse`. `Settings.get` lays each stored object over its default, so a row saved before a key existed still decodes.
- `AccountProviderId`, which is `claude` or `codex`, types `AgentProfile.provider` and `accounts.create`. The rpc boundary and `agent_account`'s CHECK refuse an added Muse account, and the settings page hides the button.
- `src/main/agents/muse/` implements `AgentProvider` with `@muse-code/sdk`, through `spawnMspConnection` and the raw `Connection`. [The integration guide](../muse-integration-guide.md) has the protocol details, the event mapping and the measured approval modes.
  - One `muse serve --trust-workspace --sandbox-network enabled`, like Codex's app-server. The handshake asks for `sessionMcp` and for `experimentalApi`, which `account/read` needs.
  - A turn is `session/start` or `session/resume` with the hinacode MCP server in `config.mcpServers`, then `turn/start` with hinacode's instructions as a leading text part.
  - Approvals come from `approval/request` and later stages from `approval/updated`. The decision goes out as `approval/decide` with the choice whose `decision` matches. Questions go back as `userInput/answer`.
  - Plan limits come from the latest `usage/changed`. Thread usage pages `view/page` over the session and its child sessions, memoized per session cursor.
- In the renderer, one `providerLabel` map replaces five copies, `ProviderIcon` maps `muse` to `RiMetaFill`, the access hints become per-agent records, and the model list grows to fit its longest name.

## Out of scope

- Added Muse accounts. Muse Code has no home variable like `CLAUDE_CONFIG_DIR`. Pointing `XDG_CONFIG_HOME` at an account home would also move the `gh` and `mise` config the agent's commands read.
- Signing Muse in from hinacode. Like the other CLIs, its own login belongs to the terminal and `muse login`.
- Skills in the composer. `skill/list` needs a loaded session, so `listCommands` returns nothing for now.
- Sub-agents in the Agents tab. The status bar counts their tokens, but `subagent` items do not become `subagent_updated` yet.
- A sandbox-off Full access. Host flags fix the sandbox posture, and a loaded session cannot move to another host while the first one runs.

## Verification

- `muse/*.test.ts` cover the pure mappings with payloads recorded from `muse` 1.4.7: models, account, plan limits, approval choices, questions, tool results and token sums, including paging from a saved cursor.
- `muse/index.integration.test.ts` runs the provider against the real `muse` binary and a loopback fake of Meta's endpoint, with no login: models and account, a text turn, a two-stage approval allowed and denied, a question, Stop, and usage paged from reminder-agent sessions. It skips when `muse` is not installed, which includes CI.
- `Settings.integration.test.ts` reads back a stored settings object that lacks a key.
- With `verify-hinacode` on Muse Wonder Full: pick the agent and model, run a reply, approve a two-stage command once, deny one, stop a `sleep 120`, relaunch and resume, and check the status bar tokens, the plan limits group and Settings > Models in both themes.
