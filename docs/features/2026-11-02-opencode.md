# opencode

Status: Building
Date: 2026-11-02

## Problem

A developer who runs open or third-party models through opencode cannot use them in HinaCode. They keep a second terminal open and lose the worktree, approvals and pull request links for that work.

## User flow

1. The model picker has an opencode tab next to Claude Code, Codex and Muse Code. It lists the models opencode reports, such as `openrouter/Claude Haiku 5.5`.
2. An opencode thread works like any other: streaming text and reasoning, tool rows, file changes, inline approvals in Supervised and Auto, the plan, Stop and the context meter.
3. While a turn runs, the composer offers Queue only. Enter queues the message, and it runs when the turn ends.
4. An agent in any thread can run an opencode sub-agent through `run_agent` only on a model the user picked under Settings, Providers, opencode, Models in the picker, or on the calling opencode thread's own model. With nothing picked it refuses and tells the agent where the user picks them. opencode lists hundreds of models, so an agent left to choose would pick one at random, often one the user has no access to.
5. The effort control shows each model's own levels, such as none to max for Claude Haiku 5.5, and hides for a model with none. `run_agent` takes the same levels, and refuses one the model does not offer with the list it does.
6. When opencode is not signed in to the model's provider, the turn fails with "opencode is not signed in. Run `opencode auth login` in a terminal, then try again".

## Design

- `ProviderId` gains `opencode`. opencode speaks the [Agent Client Protocol](https://agentclientprotocol.com) over stdio (`opencode acp`). `src/main/agents/acp/` holds a provider for any ACP agent, and `src/main/agents/opencode/index.ts` only configures it.
- Each turn runs its own `opencode acp` process, which ends with the turn. opencode keys MCP servers by directory and name within a process, so one shared process would hand two threads in the same checkout one credential. A thread's first turn creates its ACP session with the thread `cwd` and the HinaCode MCP server, and later turns call `session/load` and drop the history it replays. A failed load fails the turn rather than losing the history.
- HinaCode owns the access mode. opencode starts with `permission: "ask"` through `OPENCODE_CONFIG_CONTENT`, so it asks before every tool. The provider answers `session/request_permission` itself for Full access, and for reads and edits in Auto, and shows the approval card for the rest.
- `session/update` maps to `AgentEvent` in a pure function: message and thought chunks to deltas, `tool_call` and `tool_call_update` to paired tool events and `file_changed` for diffs, `plan` to a synthetic `update_plan` call, and `usage_update` to the context window on `turn_completed`.
- Models come from a probe session's `configOptions` (category `model`), or the older `models` field. The turn picks its model with `session/set_config_option`, or `session/set_model`. opencode reports a model's effort levels (category `thought_level`) only once that model is selected, so the probe selects each model in turn. 402 models take 0.8 seconds, and the list is cached until the app restarts. A turn then sets the thread's effort, or `default` when it has none.
- `steer` is optional on `AgentProvider`. Without it the runner queues every steer, including `send_to_thread`, pull request notices and an approval note, for after the turn. `providerInfo` in `src/shared/providers.ts` tells the renderer which agents steer and auto-compact.
- Every per-agent settings struct is built by `perProvider`, whose keys default on decode, so settings saved before opencode still decode.
- Migration `0034_opencode_provider` widens the `provider` CHECK on `thread` and `automation`.

## Out of scope

- Cursor. It speaks ACP too and needs only a config and its sign-in step on top of this provider, in its own pull request.
- Choosing which agents show up in the pickers.
- Steering, questions, sub-agents, background tasks, compaction, fork and session import. ACP has no wire form for most of them.
- Signing in from HinaCode.

## Verification

- `acp/updates.test.ts`, `acp/approvals.test.ts` and `acp/models.test.ts` cover the pure mapping. `acp/index.integration.test.ts` runs `acp/fakeAgent.ts` over stdio through a turn with a tool call, approvals in each access mode, interrupt, resume, both model shapes and a signed-out agent.
- `AgentRunner.integration.test.ts` checks that a steer and an approval note for opencode are queued.
- With `verify-hinacode` and the real `opencode` CLI: pick an opencode model, send a prompt in Supervised that writes a file, queue a follow-up while the approval card shows, allow, and check the file and the follow-up reply.
