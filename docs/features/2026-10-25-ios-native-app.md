# Native iOS app

Status: Building
Date: 2026-10-25

## Problem

The iPhone and iPad app is the Expo app in `apps/mobile`. It works, but it cannot look or behave like an iOS 26 app. Liquid Glass, the system split view, real sheets with detents, the system search field, hardware keyboard shortcuts, the system QR scanner and a String Catalog are either missing or imitated in JavaScript. On iPad, `docs/features/2026-10-24-mobile-ipad-layout.md` rebuilds by hand what `NavigationSplitView` gives for free, and still cannot read modifier keys.

## User flow

The flows match the Expo app (`apps/mobile/README.md`): pair by QR code or URL, see every paired machine's threads in one list, open a thread, read the transcript, approve or answer, send or steer, open a shell, browse files, follow pull requests, see the overview, and change settings. What changes is how each one feels:

1. The thread list is the sidebar of a `NavigationSplitView`. On iPhone and in narrow iPad windows it collapses into a stack. On a wide iPad it sits beside the open thread, and the system sidebar button hides it.
2. Toolbars, the tab bar, sheets and the search field are the system ones, so they get Liquid Glass. The composer floats over the transcript on a glass surface. Custom glass is only for controls that float over content.
3. Pairing uses VisionKit's scanner. Pasting a URL still works, and so does opening a `hinacode://connect` link.
4. A hardware keyboard sends with Command-Return, searches with Command-F, and starts a thread with Command-N.
5. Copy comes from a String Catalog, so the app follows the per-app language in iOS Settings.

## Design

- `apps/ios` holds the app. `HinaCode.xcodeproj` uses synchronized folders, so adding a file never touches `project.pbxproj`. iOS 26 is the minimum.
- `apps/ios/HinaCodeKit` is a Swift package with everything that is not a view: the wire contract, the transport, the server list and the stores. It builds for macOS too, so `swift test` runs without a simulator.
- `Contract.swift` is generated by `scripts/swift-contract.ts` from the Effect schemas in `src/shared`, following their encoded side, with the method table and routes from `contract.ts` and `routes.ts`. A literal or a tagged union reached from an answer or a push decodes an unknown member as `.unknown`, because an App Store build lags behind the desktop. CI fails when the file is stale.
- `Localizable.xcstrings` is generated by `scripts/ios-strings.ts` from the `mobile_` keys of `messages/*.json`, so the three catalogs stay the only place copy lives.
- The transport, the server hub and the stores are `@MainActor` ports of `transport.ts`, `connection.ts` and `apps/mobile/src/stores`. One thread, like the JavaScript they mirror, so each port reads side by side with its source and keeps its tests. Frames are decoded off the main actor in the socket's receive loop, in order.
- Time goes through a `Timers` protocol, so the ported transport tests drive a manual clock instead of sleeping.
- `URLSessionWebSocketTask` carries the socket. Its `maximumMessageSize` is raised above the listener's 8 MiB slow-consumer limit, and close codes 4001 and 4002 come from the delegate.
- The pairing token and the server list live in the Keychain. Preferences and drafts live in `UserDefaults`.
- Markdown is parsed by Foundation's `AttributedString(markdown:)` with full syntax, and rendered block by block in SwiftUI, so code blocks use the ported lexer and workspace images load through `fs.preview`.
- The terminal is SwiftTerm's `TerminalView`, attached with `terminal.attach` offsets. Its accessory bar replaces `terminal-keys.ts`.
- Notifications use `UserNotifications`, fired from the live socket as the Expo app does.
- Android keeps the Expo app. `apps/mobile` stays as it is; only its README stops describing iOS.

## Out of scope

- Push notifications while the app is not running. They need APNs on the desktop side.
- App Intents. Live Activities and the threads widget are in `docs/features/2026-10-26-ios-live-activities.md`.
- Migrating pairings from an Expo build on the same phone. Pairing again takes one scan.
- Attachments, editing files, the git graph, automations and secret requests, as in the Expo app.

## Verification

- `swift test --package-path apps/ios/HinaCodeKit` runs the ported tests for the transport, pairing, servers, stores and text helpers.
- `xcodebuild test` runs `HinaCodeUITests` on an iPhone and an iPad simulator against a real `hinacode serve`, walking every screen and attaching screenshots.
- `node scripts/swift-contract.ts --check` and `node scripts/ios-strings.ts --check` in CI.
